The page's "Install" section says the CLI copies files into `app/(auth)/mfa-enroll`, but the `add` command uses `--area /admin`, which means the route lands under `/admin`, not `(auth)/mfa-enroll`. This is a factual mismatch that will confuse developers checking their file system after running the command. The fix corrects the path description to match what `--area /admin` actually produces.

**Why this change:**

| Before | After |
|---|---|
| Hard-coded path `app/(auth)/mfa-enroll` contradicts the `--area /admin` flag in the very next line | Path `app/admin/mfa-enroll` matches what `--area /admin` produces, and the inline note tells readers the path is controlled by `--area` |

Correcting this prevents a support question before it happens. The `--area` callout also signals that the path changes if they pass a different value, which is the kind of detail that belongs in a setup guide.
