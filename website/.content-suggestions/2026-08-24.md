## Improvement

The "Install" section says the CLI copies files into `app/(auth)/mfa-enroll`, but that's the App Router path. The page explicitly states the kit works on **both** App Router and Pages Router, so a Pages Router user would be confused about where their files actually land. The description should cover both cases, or at minimum note that the destination path differs by router type. A concrete `--pages-router` flag example (if it exists) or a clarifying note is the right fix.

Looking at the CLI command signature — `add next --area /admin --issuer "MyApp"` — the `--area` flag scopes the protected section, but the output path description in prose is router-specific and wrong for half the audience. The simplest accurate fix is to correct the prose to describe what the flag actually does (scope the protected area) and remove the hard-coded router-specific path claim, instead noting that the CLI places files in the appropriate directory for the detected router.
